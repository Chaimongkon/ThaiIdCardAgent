### สิ่งที่พบใหม่ในการ Audit ครั้งนี้ (ไม่เคยถูกรายงานมาก่อน)

1. **หน้าเว็บไม่ auto-load อะไรเลย** — ไม่มี `useEffect` ในคอมโพเนนต์หลักทั้งไฟล์ 359 บรรทัด เปิดหน้ามาแล้วต้องกดปุ่มเองทุกอย่าง ขัดกับเป้าหมายข้อ 2 โดยตรง
2. **Token broker ไม่ออก claim `scope: card.read`** ทั้งที่ endpoint บังคับ permission นี้ → ปุ่มตรวจสอบตัวตนได้ **HTTP 403** ไม่ใช่ 501 อย่างที่เอกสารเดิมระบุ
3. **หน้าหลักเรียก route ตัวอย่าง** (`EXAMPLE_ONLY_NOT_FOR_PRODUCTION`) ซึ่ง 404 นอกโหมด development
4. **Production route `/api/member/verify` ไม่มีใครเรียกเลย** — เป็น dead code ที่มีแต่ test
5. **`MockMemberDirectory` ถูก hardcode** ใน route ตัวอย่าง โดยไม่ผ่าน `resolveMemberDirectory()` → `MEMBER_DIRECTORY_USE_MOCK` ไม่มีผลกับ route ที่หน้าหลักใช้จริง

## D. การอ่านข้อมูลบัตร

> **`BLOCKED_OFFICIAL_PROTOCOL_REQUIRED`**

| # | คำถาม | คำตอบ (อ้างอิงจริง) |
|---|---|---|
| 1 | อ่านเลขบัตรจริงได้หรือยัง | **ยังไม่ได้** |
| 2 | มี APDU ใน source หรือไม่ | **ไม่มี** — `grep -iE "\bapdu\b\|SCardTransmit"` พบเฉพาะใน comment 5 แห่ง ไม่มี `SCardTransmit` เลย |
| 3 | มี Official SDK/DLL/Protocol | **ไม่มี** — ไม่มีไฟล์ `.dll/.h/.lib/.pdf` ของ DOPA ใน repo |
| 4 | Production ใช้ Provider ตัวใด | `NotConfiguredThaiCardDataProvider` — `Service/Program.cs:51` |
| 5 | Mock Provider ใช้ที่ใด | **เฉพาะ tests** — `MockThaiCardDataProvider` ปรากฏใน `tests/` เท่านั้น ไม่มีใน DI ของ host |
| 6 | `/api/v1/card/read` ตอบอะไร | HTTP **501** `THAI_CARD_PROTOCOL_NOT_CONFIGURED` (เฉพาะเมื่อผ่าน authorization) |
| 7 | ปุ่มบนหน้าเว็บเรียก endpoint ใด | `client.readCardIdentity` → `POST /api/v1/card/read` — `ThaiIdAgentPanel.tsx:125` |
| 8 | กดปุ่มตอนนี้เกิดอะไรจริง | ⚠️ **ได้ HTTP 403 `FORBIDDEN` ไม่ใช่ 501** |

### ⚠️ ข้อบกพร่องที่พบใหม่ — Token ไม่มีสิทธิ์ `card.read`

- `/api/v1/card/read` บังคับ policy `CardReadPolicy` ซึ่ง `RequireClaim("agent_permission", "card.read")`
  → `Service/Program.cs:241`, `Service/CardReadAuthorization.cs`
- `AgentPermissionClaims.FromPrincipalClaims` อ่านสิทธิ์จาก claim `scope` / `scp` / `permissions` / `permission` เท่านั้น
- **Token broker ไม่ออก claim เหล่านี้เลย** — payload มีแค่
  `iss, aud, sub, workstation_id, jti, nbf, iat, exp` (`lib/local-agent-jwt.ts:35-44`)

**ผลลัพธ์:** ปุ่มถูกปฏิเสธที่ชั้น authorization **ก่อน**ถึง provider ด้วยซ้ำ
นี่คือ integration break จริง ไม่ใช่แค่ provider ที่ยังไม่มี

> หมายเหตุ: ถ้ารัน Agent ในโหมด Development จะได้ **401** แทน เพราะ `AuthenticateDevelopment` ต้องการ header `X-Agent-Development-Key` แต่เบราว์เซอร์ส่ง `Authorization: Bearer` — ทั้งสองกรณีไม่ถึง 501

## M. สรุป Flow ที่ทำงานได้จริงวันนี้

1. **เปิดหน้าเว็บ `http://localhost:3000/`**
   → แสดง Health "Not checked", Reader count 0, Card state "NoReader"
   → **ไม่มีการเรียก API ใด ๆ อัตโนมัติ**

2. **ต้องกด "Check Agent" เอง** → `GET /api/v1/health` → ✅ สำเร็จ

3. **ต้องกด "Refresh Readers" เอง** → `GET /api/v1/readers` → ✅ เห็นชื่อเครื่องอ่านจริง

4. **ต้องกด "Refresh Card Status" เอง** → `GET /api/v1/card/status` → ✅ เห็น CardPresent/NoCard จริง
   หรือกด "Connect Events" เพื่อรับ SSE

5. **ปุ่มที่กดได้:** Check Agent · Refresh Readers · Refresh Card Status · Read ATR · Connect/Disconnect Events
   · ปุ่ม "ตรวจสอบตัวตนด้วยบัตรประชาชน" enable เมื่อครบ 3 เงื่อนไข
   · ปุ่ม "Card Read" disabled ถาวร

6. **อ่านได้จริง:** ชื่อเครื่องอ่าน, สถานะบัตร, ATR **เท่านั้น**

7. **Flow หยุดที่:** กดปุ่มตรวจสอบตัวตน → `POST /api/v1/card/read` → **HTTP 403 FORBIDDEN**
   (token ไม่มี `card.read`) → หน้าจอขึ้น "ไม่มีสิทธิ์อ่านข้อมูลบัตร"
   · แม้แก้ scope แล้วก็จะได้ **501** ต่อทันที

8. **Mock Flow ต้องเข้าที่:** `http://localhost:3000/dev/member-verification` (`npm run dev` เท่านั้น)
   → เลือก 1 ใน 4 กรณี → เห็น Member Card ครบ
   → **ไม่มีลิงก์จากหน้าหลัก**

9. **Production Flow ขาด:** DOPA provider · `card.read` scope ใน broker · member DB จริง · SSO · audit persistence · การเรียก `/api/member/verify`

### 1. ตอนนี้โปรแกรมอ่านเลขบัตรจริงได้หรือยัง

### 2. ตอนนี้โปรแกรมค้นฐานสมาชิกจริงได้หรือยัง

**ยังไม่ได้** — ไม่มี engine, driver, connection string, schema, SQL
Production = `NotConfiguredMemberDirectory`
ที่ทำงานอยู่คือ `MockMemberDirectory` ผ่าน route ตัวอย่างเท่านั้น

### 3. หน้าเว็บปัจจุบันสามารถทำ Flow หลักได้ถึงขั้นไหน

ถึง **ขั้นที่ 4 จาก 9** ของเป้าหมาย

- ❌ กดปุ่มตรวจสอบตัวตนแล้วหยุดที่ 403

- ℹ️ Member Card เห็นได้เฉพาะที่ `/dev/member-verification`
